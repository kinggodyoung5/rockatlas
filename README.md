# ROCK ATLAS — 락밴드 탐험지도

서양 록 밴드를 장르와 영향 관계를 따라 발견하는 탐험형 웹사이트의 첫 프로토타입입니다. 한국 밴드는 현재 범위에서 제외하며, 영어권에 한정하지 않고 인지도가 있는 유럽·북미·오세아니아 밴드를 다룹니다.

## 지금 구현된 범위

- 9개 대분류 장르 탐색 홈
- 33개 밴드와 장르·시대·국가·서브장르 검색
- 밴드별 결성 연도, 출신지, 활동 기간, 주요 멤버, 스타일 설명
- 대표곡의 앨범·연도·감상 안내와 곡별 외부 YouTube 링크, 공식 채널 바로가기
- 밴드 사이의 영향·유사성·동시대 장면을 연결한 탐험지도
- 브라우저에 저장되는 밴드 즐겨찾기와 최근 탐험 기록
- 관계 노드에서 그다음 연결을 미리 보여 주는 2단계 탐색 힌트
- 검수 완료된 Wikimedia Commons 대표 이미지와 저작자·라이선스 표시
- 출처와 이미지 저작권 상태를 저장할 수 있는 데이터 구조
- 모바일·태블릿·데스크톱 반응형 UI
- 코드 없이 밴드 추가·수정·분류·관계 연결·JSON 백업을 할 수 있는 로컬 Studio

> 이 버전의 설명과 관계 데이터는 제품 구조를 검증하기 위한 **편집 초안**입니다. 공개 서비스로 전환하기 전에 사실 관계, YouTube 영상 상태, Wikimedia 원본 파일의 라이선스를 항목별로 검수해야 합니다.

## 장르 체계 초안

탐색성을 위해 경계가 비교적 선명한 큰 분류를 사용합니다. 세부 장르는 다음과 같이 상위 장르에 접어 넣었습니다.

| 대분류 | 함께 다루는 세부 장르 예시 |
|---|---|
| 클래식 록 | 블루스 록, 포크 록, 사이키델릭 록, 루츠 록 |
| 하드 록 | 글램 록, 글램 메탈, 부기 록, 아레나 록 |
| 프로그레시브·아트 록 | 아트 록, 네오 프로그, 스페이스 록, 포스트 프로그 |
| 펑크 록 | 개러지 펑크, 하드코어 펑크, 초기 포스트 펑크 |
| 얼터너티브·인디 록 | 인디 록, 노이즈 록, 슈게이즈, 브릿팝, 포스트 록 |
| 그런지 | 시애틀 사운드, 슬러지 성향 얼터너티브 |
| 헤비 메탈 | NWOBHM, 스피드·파워·스래시 메탈 |
| 익스트림 메탈 | 데스·블랙·멜로딕 데스 메탈, 그라인드코어 |
| 고딕·인더스트리얼 | 고딕 록, 다크웨이브, 인더스트리얼 록·메탈 |

각 밴드는 목록에서 `primaryGenre` 한 곳에만 등장합니다. 겹치는 성향은 `genreIds`에 여러 개 저장하고 상세 화면의 “장르 교차점”에서 보여 줍니다.

## 실행 방법

Node.js 20.19 이상 또는 22.12 이상을 권장합니다.

```bash
npm install
npm run dev
```

콘텐츠 운영 Studio 실행:

```bash
npm run studio
```

브라우저에서 터미널에 표시된 주소의 `?studio=1` 페이지를 엽니다(예: `http://127.0.0.1:5173/?studio=1`). 디자인 Studio에서는 브랜드·문구, 폰트 프리셋과 배율, 로컬 폰트 업로드와 본문·제목 적용 범위·굵기·이탤릭, 색상, 히어로 이미지 업로드, 섹션 표시·순서, PC·모바일 미리보기와 9개 장르 카드를 관리합니다. 데이터 관리에서는 CSV 일괄 입력, 휴지통, 최근 20회 자동 백업·복구, 중복·관계·검수 경고와 출처 상태를 관리합니다. “전체 링크·이미지 상태” 검사는 공개 출처·대표곡·이미지·업로드 폰트를 정상/이동/접근 제한/끊김/확인 실패로 분류합니다. 기존 밴드를 선택해 수정하거나 “새 밴드”로 초안을 만들고, 외부 식별자 구역에서 아티스트 이름을 검색해 Wikidata·MusicBrainz 후보를 직접 선택할 수 있습니다. MusicBrainz 후보를 고르면 식별자와 함께 결성지·국가·활동연도 초안도 반영됩니다. “전체 저장”을 누르면 `src/data/catalog.json`에 반영됩니다. 새 밴드는 기본적으로 공개 목록에서 숨겨지는 `draft` 상태입니다. 저장 API와 외부 검색·상태 검사 프록시는 로컬 Vite 개발 서버에서만 동작하며 배포된 정적 사이트에는 노출되지 않습니다.

배포용 결과 확인:

```bash
npm run build
npm run preview
```

데이터 검수 현황과 외부 식별자 후보 확인:

```bash
npm run review
npm run validate:data
npm run audit:facts -- --strict
npm run review:videos
npm run audit:relations -- --strict
npm run collect:review -- --band=radiohead
```

`collect:review`는 Wikipedia 문서에 연결된 Wikidata 항목과 MusicBrainz 검색 후보를 보여 줄 뿐 데이터를 자동 승인하지 않습니다. 이름·결성 연도·국가를 대조한 뒤 `externalId`와 검수 기록을 반영합니다. 요청 제한이 발생하면 지수 백오프로 재시도합니다. `audit:facts`는 승인된 식별자에서 결성 연도·국가·활동 시기·멤버 관계를 다시 읽어 편집 데이터와 교차 감사합니다. `validate:data`는 중복 식별자, 잘못된 관계 대상, 장르·트랙 ID 오류를 검사하고, `audit:relations`는 관계 출처, 역방향 누락, 양방향 종류 불일치를 점검합니다. `npm run review`는 현재 검수 진행률을 보여 주며, 모든 밴드가 5개 기준을 통과한 시점에는 `npm run review:strict`를 사용합니다.


## 데이터와 저작권 원칙

`SourceRef`는 정보 출처, 접근일, 교차 확인 메모를 저장합니다. `ImageCredit`은 원본 URL, 저작자, 라이선스, 검수 상태를 저장합니다.

33개 대표 이미지는 Wikimedia Commons 원본 파일 페이지에서 저작자와 자유 라이선스를 확인해 정적 URL과 함께 저장했습니다. Wikipedia PageImages API는 앞으로 추가되는 미검수 밴드의 후보 프리뷰에만 사용하며, 후보 이미지가 곧 자유로운 재사용을 의미하지 않으므로 검수 전에는 UI에도 “라이선스 검토 필요”로 표시합니다.

기존 대표곡의 공식 채널·IFrame 검수 기록은 운영 메타데이터로 보존합니다. 공개 상세 화면은 임베드 가능 여부와 무관하게 모든 대표곡을 앨범·연도·한 줄 감상 안내와 함께 표시하고, 각 곡을 YouTube 외부 페이지로 연결합니다. 아티스트 공식 채널 바로가기도 항상 함께 제공합니다. `npm run search:videos -- --all --blocked-only --official-only`와 내부 `?review=videos` 화면은 링크 교체가 필요할 때 쓰는 운영 도구입니다.

밴드 관계 99개에는 방향과 관계 종류를 뒷받침하는 편집 출처를 연결했습니다. 역방향이 함께 있는 관계는 영향/영향받음처럼 호환되는 종류인지 자동 검사하며, 직접 영향처럼 의미상 방향성이 있는 29개 관계는 단방향으로 유지합니다.

## 기술 구성

- React 19 + TypeScript + Vite
- Tailwind CSS 4 (`@tailwindcss/vite`)
- Lucide React 아이콘
- 외부 데이터 프리뷰: MediaWiki API
- 콘텐츠 저장: 로컬 Studio + 버전 관리 가능한 JSON 카탈로그
- 탐험 상태 저장: URL 해시와 브라우저 `localStorage`

댓글, 로그인, 기기 간 동기화 같은 서버 영속 기능은 아직 포함하지 않았습니다. 다음 단계에서 Supabase 등 별도 백엔드를 선택한 뒤 추가하는 편이 안전합니다.

현재 즐겨찾기와 최근 탐험 기록은 계정 없이 이 브라우저의 `localStorage`에만 저장됩니다. 다른 기기와 동기화되는 계정 기반 저장은 아직 포함하지 않았습니다.

## 배포 메모

`vite.config.ts`의 `base: './'` 설정으로 GitHub Pages와 일반 정적 호스팅에서 하위 경로 배포가 가능합니다. `.github/workflows/deploy-pages.yml`은 `main` 브랜치에 푸시할 때 데이터 검사, 프로덕션 빌드, Pages 배포를 자동 실행합니다. GitHub 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 한 번 지정해야 합니다. Studio에서 생성한 `public/uploads` 이미지·폰트도 커밋해야 배포 결과에 포함됩니다.
