# 1단계 — 리서치 전용 프롬프트 (새 채팅에 이것만 붙여넣을 것)

이 문서는 짧다. 스키마도, JSON 형식도, 환각 방지 규칙도 여기엔 없다 — 검색만 시킨다. 형식 변환은 2단계(`GEMINI_STEP2_FORMAT.md`)에서 별도로 한다. 한 번에 너무 많은 걸 시키면 도구 호출이 씹히니, 이 단계는 "검색해서 사실 모으기"만 한다.

---

## 0단계 — 검색 도구가 실제로 되는지부터 증명해라 (건너뛰지 말 것)

본 작업을 시작하기 전에, 다음 한 문장만 먼저 실행해라: **`Travis band formed year` 를 지금 실제로 검색하고, 검색 결과에 뜬 원문 스니펫(글자 그대로)과 그 결과가 나온 페이지의 URL을 그대로 보여줘라.**

이걸 하지 않고 바로 본 작업으로 넘어가지 마라. 만약 이 단계에서 검색이 실패하거나 에러가 나면, "정책 때문에 못 한다"거나 "환각 방지 규칙 때문에 방어적으로 답한다" 같은 네 나름의 해석이나 변명을 늘어놓지 말고, **실제로 무슨 일이 일어났는지 시스템이 준 원문 에러 메시지를 그대로, 한 글자도 바꾸지 말고 출력해라.** 사용자가 그 원문을 보고 직접 판단할 것이다.

이 0단계가 성공하면 (실제 검색 결과 스니펫과 URL을 보여줬으면) 본 작업으로 넘어가라.

---

아래 밴드들 각각에 대해 실제로 웹 검색을 실행해서 사실을 조사해줘. 절대 상상하거나 기억으로 채우지 마라 — 검색 결과에 실제로 뜬 내용과 URL만 써라.

**"확인 필요"나 "검색했지만 못 찾음"은 최후의 수단이다, 첫 시도 실패의 변명이 아니다.** 검색 결과가 없거나 애매하면 최소 2번은 다른 키워드로 다시 검색해봐라 (예: 밴드명만으로 실패하면 "밴드명 official site", "밴드명 discography" 등으로 바꿔서). 두 번 이상 다른 방식으로 시도했는데도 못 찾았을 때만 "검색했지만 못 찾음"이라고 적고, 그때는 **어떤 검색어들을 시도했는지** 함께 적어라. "이 규칙이 엄격해서 방어적으로 답했다"는 식의 자기 해석은 쓰지 마라 — 실제로 뭘 검색했고 뭐가 나왔는지 사실만 적어라.

밴드를 하나씩 순서대로 처리해라. 밴드 하나당 아래 7개 항목을 각각 실제로 검색해서 채우고, 다 끝나면 "[밴드명] 조사 완료"라고 쓰고 다음 밴드로 넘어가라.

**조사할 밴드:**
1. Travis
2. Imagine Dragons
3. Oasis

**밴드 하나당 조사 항목 (각 항목마다 검색을 실행할 것):**

1. `밴드명 wikipedia` 검색 → 결성 연도, 결성 도시/국가, 국가 코드(ISO 2자리), 활동 기간, 장르(영어 원문 그대로), 현재 멤버 이름과 역할
2. `밴드명 wikidata` 검색 → Wikidata 페이지 URL과 Q번호 (주소창에 실제로 뜬 값만)
3. `밴드명 musicbrainz` 검색 → MusicBrainz 아티스트 페이지 URL과 UUID (주소창에 실제로 뜬 값만)
4. `밴드명 site:commons.wikimedia.org` 검색 → 라이선스가 명확한 밴드 사진 1장의 파일명, 촬영자/업로더 이름, 라이선스 종류, 파일 페이지 URL
5. `밴드명 노래제목 official video youtube` 검색 (대표곡 2곡 각각) → 곡 제목, 발매연도, 앨범명, 실제 watch URL, 업로드한 채널명
6. 이미 열어본 위키피디아 페이지 안에서 → 이 밴드가 다른 유명 밴드에게 영향을 주거나 받았다는 문장, 또는 같은 음악 씬으로 묶인다는 문장이 있는지 확인. 있으면 그 문장과 어느 밴드인지, 출처 URL을 적어라. 없으면 "관계 없음"이라고 적어라.
7. 위 모든 항목에서 검색해도 못 찾은 게 있으면 그 항목만 "검색했지만 못 찾음"이라고 솔직히 적어라. 절대 지어내지 마라.

**출력 형식:** 밴드별로 나눠서, 항목 1~7을 번호 그대로 나열하는 목록 형식으로 써라. JSON으로 변환하려 하지 마라 — 그건 다음 단계에서 한다. 지금은 순수하게 조사한 사실만 나열하면 된다.

세 밴드 다 끝나면 "리서치 완료"라고 말해줘.
