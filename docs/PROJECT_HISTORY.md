## 1. 모든 AI가 작업 시작 전에 반드시 할 일

1. 이 `PROJECT_STATUS.md`를 처음부터 끝까지 읽는다.
2. 현재 브랜치, `git status --short`, 최근 커밋, `git diff`를 확인한다.
3. 미커밋 변경은 사용자의 작업일 수 있으므로 절대 임의로 되돌리거나 덮어쓰지 않는다.
4. 사용자가 Studio에서 새 밴드를 추가한 상태로 재개하는 경우가 가장 흔하다 — `git show HEAD:src/data/catalog.json`과 현재 파일의 밴드 수·id 목록을 비교해 신규 밴드를 찾아 3번 항목 체크리스트부터 진행한다.
5. 사용자가 "확인하고 계속", "다음 단계", "어디까지 됐나"라고 하면 별도 인수인계를 요구하지 않는다. 현재 상태와 바로 시작할 단계를 짧게 보고하고 이어서 진행한다.
6. 상태 문서가 오래됐거나 실제 Git과 다르면 먼저 이 문서를 갱신한다.
7. 사용자 검토 전에는 `main` 병합·배포를 하지 않는다(단, 이 프로젝트에서는 사용자가 매번 "반영해달라"는 취지로 명시적으로 요청해왔으므로 유사한 요청이 있으면 동일하게 처리 가능 — 확실치 않으면 먼저 확인).

## 2. 모든 AI가 작업 종료·교체 전에 반드시 할 일

하루 작업 종료, Codex↔Claude 교체, 큰 단계 완료 시 다음을 이 문서에 기록한다.

1. 완료한 내용과 실제 커밋 ID
2. 저장했지만 커밋하지 않은 파일
3. 중단된 작업과 중단 지점
4. 재현 가능한 오류와 검사 결과
5. 다음 AI가 바로 실행할 작업을 우선순위 순서로 작성
6. `main` 병합·배포 여부와 원격 푸시 여부
7. 새로 정한 사용자 요구사항과 하지 않기로 한 범위

검사가 실패한 상태를 "완료"라고 기록하지 않는다. 커밋하지 않은 변경은 반드시 **진행 중 작업**에 남긴다.

## 7. Git과 Studio 저장의 차이

- Studio `저장`: `src/data/catalog.json`을 변경하고 로컬 복구 이력을 만든다.
- Git `commit`: 변경 내용을 로컬 Git 역사에 기록한다.
- Git `push`: 커밋을 GitHub 원격 저장소에 올린다.
- 같은 PC·같은 폴더의 다른 AI는 `git diff`로 미커밋 변경을 볼 수 있다.
- GitHub만 보는 AI는 커밋·푸시되지 않은 변경을 알 수 없다.
- 브라우저에서 편집했지만 Studio 저장을 누르지 않은 값은 다른 AI도 알 수 없다.

## 8. Studio 대표곡 저장 버그 (2026-07-23, 수정 완료)

대표곡 입력창에 `|` 구분자 없이 제목만 쓰고 포커스를 벗어나면(`youtubeIdFromInput()`이 `undefined.trim()` 호출) 예외가 던져져 편집 내용이 React 상태에 아예 반영되지 않았다 — "전체 저장"을 눌러도 저장될 대상 자체가 없던 것. `youtubeIdFromInput`/`splitList`에 undefined 가드를 추가해 수정, 브라우저 재현 테스트로 확인 완료. 이 버그로 사라진 과거 입력 내용은 git 히스토리·로컬 백업(`catalog-history.json`, 최근 20개 저장만 보관) 어디에도 없어 복구 불가능하다.

**앞으로 비슷한 필드를 추가할 때 주의할 패턴**: `line.split('|')` 결과를 구조분해할 때 뒤쪽 필드는 값이 없으면 `undefined`가 된다. 그 값에 바로 `.trim()`/`.split()` 등을 호출하는 대신 `value ?? ''`로 기본값을 준 뒤 호출할 것.
